# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository

`page-snapshot-extension/` is PageKeep (called Page Snapshot up to 1.1.1; the folder and the repository keep the old name), a plain-JavaScript Manifest V3 extension for Chromium browsers (Chrome, Opera, Edge…) that saves the active tab as an offline ZIP (see its `README.md`). It has no build step and no npm dependencies: load the folder unpacked on the browser's extensions page. It previously lived in `asantos43/projetos-ia-genericos` under `chrome-extensions/`, where a frozen copy remains; do not edit that copy.

Architecture: the toolbar button (or Alt+Shift+S) opens `popup.html`, the action popup under the icon, which only renders the capture and sends OK / Cancel / Download again; the captured tab stays visible, so Chrome does not throttle its timers while carousels are stepped. `background.js` (a module service worker) keeps the capture ("job") in `chrome.storage.session`, sets the icon badge, and runs the capture in an offscreen document (`offscreen.html`), which lives on when the popup closes; the offscreen page only has `chrome.runtime`, so it asks `background.js` for every `chrome.tabs` / `scripting` / `debugger` / `downloads` call. One capture at a time. No host permissions: `activeTab` gives the captured tab, and files the tab had not loaded are downloaded by the tab itself through the debugger (`Network.loadNetworkResource`); see `docs/STORE-POLICY.md`, the Chrome Web Store checklist that every release must pass. `inpage.js` runs in the tab and snapshots the live DOM (and steps through carousels, and turns Monaco editors into plain text), with `inpage-main.js` reading editor text from the page's own JS world. `offscreen.js` (Cancel makes `background.js` tell `inpage.js` to stop and restore carousels, then close the offscreen document) reads the resources the tab already loaded through `chrome.debugger`, downloads the rest (throttled per host, retrying 429/503), rewrites URLs and builds the ZIP with `lib/zip.js`. The full help page is `help.html` (English) and `help.pt_BR.html`, linked from the popup's Help through the `help_page` message. Every text is in `_locales/en` and `_locales/pt_BR` (same keys); the offscreen page has no `chrome.i18n`, so it publishes texts as `{ key, args }` and `popup.js` translates them. `lib/helpers.js` holds the pure, Node-testable helpers. `lib/interactions.js` is the small local script embedded in snapshots to restore accordions, tabs, carousels and editor buttons offline.

Rules that shape the design:

- A snapshot must never contact the network when opened: the page's own scripts, `ping` attributes and cross-origin iframes are removed, and references to anything that could not be saved are dropped rather than left pointing online.
- Local scripts that restore page behaviour offline are welcome (extend `lib/interactions.js` when interactive content is already in the saved DOM); they must be self-contained and never use the network.

`PRIVACY.md` (English and Portuguese) is the privacy policy, published as the public gist https://gist.github.com/asantos43/a0566af48d0894dc44b72bee43b22da8 for the store; after changing it, run `gh gist edit a0566af48d0894dc44b72bee43b22da8 --filename PRIVACY.md PRIVACY.md` (confirm with the user first: it is an external action). `store/` holds the Chrome Web Store listing: `README.md` (field by field), `PUBLISHING.md` (the dashboard steps, in Portuguese), the descriptions (`description.en.txt`, `description.pt_BR.txt`, plain text, naming no other product) and the pictures. `docs/DEVELOPMENT.md` holds the background that is not in the code: tool versions, how to load and test in each browser, versioning and releases, and how this repository was extracted.

## Tests

`tests/` runs the extension in a real Chromium with Playwright (the only npm dependency; `npm install` there). Playwright's own Chromium, in `~/.cache/ms-playwright`, is required: the Flatpak Google Chrome/Edge are branded builds that ignore `--load-extension`, so they cannot load an unpacked extension under automation.

- `npm run smoke` (`node smoke.mjs [extension folder]`, default `../page-snapshot-extension`): the extension loads and each top-level `.html` page opens without an uncaught error.
- `npm run carousel` (`node carousel.mjs`): end-to-end capture of a local test page with a 12-item carousel and files from a second site the extension has no permission for, through the real popup (`chrome.action.openPopup`): all items recorded, the page put back on item 1, the ZIP downloaded and its carousel working offline with no network request, OK, closing the popup mid-capture, Cancel (carousel restored, nothing saved, debugger released). Playwright cannot reach the real popup's page, so the test opens `popup.html` in its own window to click its buttons; `activeTab` cannot be granted under automation, so it loads a copy of the extension with the test site as a host permission.
- `npm run store-policy` (`node store-policy.mjs`): static checks from `docs/STORE-POLICY.md`: the exact permission list (each justified there), no host permissions, no eval or remote code, no network host named in the code, the two locales complete and every message used, name/description within the store's limits in each language, the store pictures' sizes and descriptions, icons without third-party metadata.
- `npm run screenshots` (`node screenshots.mjs [--lang=en|pt-BR] [--out=<folder>]`): real screenshots of the popup (running, done, failed file, Help open) and of the saved page opened offline, from a local example news site reached as `http://harbortimes.example/` (a made-up news site, `tests/example-site.mjs`); by default both languages into `page-snapshot-extension/images/screenshots/<en|pt_BR>/`, used by `help.html` / `help.pt_BR.html` and the READMEs. Each shot is checked first (language, no untranslated key, the right moment of the capture) and the script exits 1 otherwise; a capture in progress is frozen in the popup at the checked moment. Rerun it when the popup's look or texts change, and look at the images before committing.
- `node readme-images.mjs [--url=…] [--lang=pt-BR]` (needs the internet): captures a real site (default https://www.tudogostoso.com.br/) and writes the popup and the saved copy opened offline to `docs/images/readme/`, for the main README only; fails if the copy tries to reach the network (it found the `compression-dictionary` bug). Pictures of third-party sites never go into `page-snapshot-extension/` or `store/`.
- `node store-images.mjs`: the Chrome Web Store pictures in `store/images/<en|pt_BR>/` (five 1280×800 screenshots, one per feature, the 440×280 small tile and the 1400×560 marquee), built from the extension's screenshots; run `npm run screenshots` first if the popup changed.
- `npm run publish-script` (`node publish-script.mjs`): runs the store upload script against a fake Chrome Web Store on 127.0.0.1 with a throw-away key: no secrets (notice, exit 0), a normal upload (signed token, exact zip, status, publish), a rejected package, a wrong key.
- The rest of the capture logic was verified with throw-away jsdom harnesses that are not in the repo.

When behaviour changes, update `page-snapshot-extension/README.md` and add a line under `## [Unreleased]` in `CHANGELOG.md`.

`.claude/settings.json` pre-approves `npm install`, the smoke test, `node --check` and read-only git commands.

## Releases

`.github/workflows/release.yml` publishes a release each time a pull request is merged into `main` (and on demand via `workflow_dispatch`): it releases the manifest version if it has no tag yet, otherwise raises the last number (1.0.0 → 1.0.1) and commits "Version x.y.z" to `main`, runs the smoke, carousel, store-policy and publish-script tests, zips the extension (plus `CHANGELOG.md`) as `pagekeep-<version>.zip` and publishes `v<version>`. After publishing the GitHub release it sends the same zip to the Chrome Web Store for review (`.github/scripts/publish-to-chrome-web-store.sh`, API v2, service account; only with the `CWS_PUBLISHER_ID`, `CWS_ITEM_ID` and `CWS_SERVICE_ACCOUNT_KEY` secrets, which the user sets, and never for a pre-release). A pull request labelled `no-release` is merged without a release. For a minor or major release, raise `version` in `manifest.json` inside the pull request. Every pull request adds its user-facing changes as lines under `## [Unreleased]` in `CHANGELOG.md`; the release moves them into the version's section and uses that section as the release notes. After a merge, `git pull` picks up the bot's version commit. See `docs/DEVELOPMENT.md` → Versions and releases.

## Git policy

The remote is `origin` = https://github.com/asantos43/webpage-snapshot (private; keep it private). The default branch is `main`. Never commit or push directly to `main`: make every change on its own branch created from an up-to-date `main`, push the branch and open a pull request (`gh pr create`); the user reviews it and decides when to merge. The only commits that land on `main` by themselves are the release workflow's "Version x.y.z" bumps.
